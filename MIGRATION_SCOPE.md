# Migration scope

## Что означает «весь проект»
Полный перенос делится на три слоя.

### A. Физически доступные первичные файлы
Это жёсткий слой, который должен быть сохранён побайтово либо lossless-реконструируемо:
- экспортированные чаты (`messages12.html`, TXT);
- скриншоты;
- видео;
- исходные рабочие Markdown-файлы.

Для каждого файла нужен размер, SHA-256 и статус фактической миграции.

### B. Рабочая аналитическая база
Документы `00`–`13`, датированные update-файлы, реестры, гипотезы, правила анализа. Это редактируемый слой Git с историей изменений. Главный источник истины: `09_COMBINED_MASTER.md`, затем `00_INDEX.md`.

### C. Ветки ChatGPT, для которых нет полного физического экспорта
Такие ветки фиксируются в `sources/chat_catalog.md` как `transcript-pending` или `partial-source`. Сводки памяти и проектные резюме используются только как вторичный навигационный слой. Они не выдаются за полный первичный транскрипт.

## Критерий завершения
Миграция считается полной только когда:
1. каждый известный физически доступный первичный файл имеет сохранённое полное содержимое и SHA-256;
2. все известные проектные ветки имеют либо полный экспорт, либо явный статус `transcript-unavailable/pending`;
3. `tools/verify_archive.py` и CI проверяют reconstructable-источники;
4. PR прошёл итоговый аудит;
5. только после этого изменения попадают в `main`.

## Запрет на красивую бухгалтерию
Manifest, карточка источника, краткое содержание или список имён не равны переносу самого файла. В реестре это всегда отмечается отдельно.

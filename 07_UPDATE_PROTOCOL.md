# Протокол обновления

## Приоритет
Любое обновление сначала сверяется с `09_COMBINED_MASTER.md`, затем с `00_INDEX.md`. Старые гипотезы не стираются: изменение фиксируется новой записью и историей Git.

## Когда появляется новый материал
1. Определить тип источника: screenshot / chat-export / text-transcript / user-report / external-reference.
2. По возможности сохранить исходник в `sources/`; если бинарное вложение пока не архивировано, зарегистрировать его как `PROJECT_CHAT_SCREENSHOTS` с пометкой `binary-pending`.
3. Добавить/обновить запись в `08_SOURCE_REGISTRY.md`.
4. В `02_TIMELINE.md` внести только наблюдаемое и прямые слова, отдельно маркируя REPORT.
5. Если данные влияют на версию, обновить `03_HYPOTHESES_AND_CONFIDENCE.md`: за / против / альтернативы / уровень уверенности.
6. Если меняется общий вывод, обновить `09_COMBINED_MASTER.md`.
7. Для крупных периодов создавать отдельный датированный файл в `kris/`.
8. В сообщении коммита указывать, что изменено и на каком основании.

## Запреты
- не смешивать факт и мотив;
- не повышать уверенность только из-за красивой связности версии;
- не использовать сон как доказательство конкретного намерения;
- не объявлять пользовательское наблюдение независимым фактом без маркировки;
- не удалять неудобные старые версии;
- не исправлять старую запись задним числом без журнала изменения;
- не превращать отсутствие опровержения в подтверждение.
